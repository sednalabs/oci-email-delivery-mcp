# OCI Email Delivery MCP Live Proof Matrix

This matrix records the no-send proof required before using the adapter for
pilot monitoring.

| evidence line | required proof | current status |
| --- | --- | --- |
| Server shape | Standalone curated stdio intent server built with `mcp-toolkit-rs`. | implemented locally |
| Toolkit template | `templates/curated-stdio-intent-server`. | implemented locally |
| Intent tools | `oci_email_status`, `oci_email_metrics`, `oci_email_ledger_window`, `oci_email_events`, `oci_email_message_engagement`, `oci_email_logging_status`, `oci_email_logging_enablement_plan`, `oci_email_trace_message`, `oci_email_suppressions`, `oci_email_suppression_delta`, `oci_email_watch_window`, `oci_email_send_readiness`, `oci_email_traceability_audit`, `oci_email_monitoring_snapshot_artifact`. | implemented locally |
| Toolkit contract tests | Schema snapshot and real stdio `tools/list` smoke. | implemented locally |
| Domain output contract tests | Fixture-backed output, redaction, missing-auth, invalid-filter, and missing-metric tests. | implemented locally |
| Live no-send proof | OCI profile read-only status, metric discovery/summarize, log search, and suppression query without `submit-email` or mutation commands. | passed as no-send/blocked on 2026-06-30; see `docs/no-send-live-proof-2026-06-30.md` |
| Logging configuration visibility | `oci_email_logging_status` inventories visible OCI service-log configuration and blocks when no active Email Delivery service log is visible; when a resource domain or resource id is supplied it reports active matching resource-log counts, without enabling or mutating logs. | implemented with fixture tests; pending live configured-alias proof after hosted artifact install |
| Logging enablement plan | `oci_email_logging_enablement_plan` turns the current logging-status readback into a redacted, no-mutation operator plan for Email Domain service-log categories, approval gates, and post-enable proof; a resource domain can satisfy resource-scoped proof after read-only Email Domain resolution. | implemented with fixture tests; pending hosted artifact install |
| Suppression aggregate proof | `oci_email_suppressions` fetches all pages for counts and returns bounded redacted sample rows plus `total_matched`, `totals.hard_bounce`, `totals.by_reason`, capped `totals.by_recipient_domain`, `totals.by_recipient_domain_omitted`, count confidence, and timestamp bounds so clean-audience and stop-gate reconciliation does not depend on raw recipients or unbounded bucket output. | implemented with fixture tests; pending hosted artifact install |
| Suppression delta proof | `oci_email_suppression_delta` compares full active suppressions with a bounded UTC window and returns clean, degraded, or blocked evidence without raw recipients. New active hard-bounce or complaint suppressions block; no-sample or lower-bound reads degrade. | implemented with fixture tests; pending hosted artifact install |
| Local send ledger proof | Configured private JSONL ledger can be summarized by UTC window with hashes/domains only and no raw recipients. Provider/sender/campaign/batch aliases are reconciled before selector narrowing, so contradictory rows claiming the requested scope remain blocking invalid evidence. Optional message-id or correlation-id filters narrow large windows before the returned-row cap. | implemented with fixture tests; pending live configured ledger path |
| Composed watch-window proof | `oci_email_watch_window` combines profile status, resource-scoped logging-status proof, scoped metrics, scoped events, optional trace, and bounded suppression-window evidence for one UTC window while still returning `send_authorized=false`. | implemented with fixture tests; pending live configured-alias proof after hosted artifact install |
| Composed send readiness proof | `oci_email_send_readiness` combines watch-window proof with local ledger row-count, trace-key, recipient-key, and every-row OCI Email Delivery provider-authority gates while still returning `send_authorized=false`; missing, non-OCI, or mixed-provider rows block readiness. | implemented with fixture tests; pending live seed/cohort ledger rows and log traceability |
| Exact traceability proof | v2 `oci_email_traceability_audit` emits `schema=oci-email-delivery.traceability-audit.v2`. Consumers branch on `log_evidence_state`, `trace_evidence_state`, and `ledger_evidence_state`: complete empty combined-log or trace reads are `0`, while incomplete or unavailable combined-log/trace evidence is `null`; ledger scalars are `null` only when the ledger is unavailable and otherwise preserve observed `0`/`false`/`true`; trace can also be `not_requested`. `provider_evidence_available` records observed metric/log existence only, never provider acceptance, relay, or exact proof. Exact proof requires complete requested log evidence, exactly one matching valid uncapped ledger row with unambiguous OCI Email Delivery provider authority, and same-row trace-and-recipient overlap across one complete provider message/recipient identity; missing, non-OCI, or contradictory ledger provider identity blocks proof, and a header-traced row's present message-id hash must also match the provider event identity. Multiple provider lifecycle events may relate to the identity, while heterogeneous provider trace identities or multiple ledger rows block proof. | implemented with fixture-backed v2 contract coverage; pending live configured ledger path and matching provider log events |
| Exact message engagement proof | `oci_email_message_engagement` reports redacted per-signal open/click/list-unsubscribe state for one exact Message-ID and bounded window. A validated source domain is mandatory for proof; an unscoped request is unavailable without a provider query. Conventional Message-ID values may use one enclosing angle-bracket pair. Nullable counts distinguish complete zero from unavailable evidence; null/provider failures, capped reads, contradictory backend reports, unknown actions, source mismatch, malformed identities/timestamps, and missing exact identity never become `not_observed`. The composed tool rebinds filters, window, scope, limits, event identities, uncapped evidence and recomputed counts before accepting a state. Overall `proven_active` requires all three required signals; a complete subset remains `not_observed`. Duplicate summaries retain provider counts and are called out. Transport ingress remains explicitly unavailable because this parser does not inspect or attest SMTP/SubmitEmail ingress; this remains no-send evidence. | implemented locally with focused internal and external contract coverage; pending hosted artifact and no-send live readback |
| Durable private snapshots | `oci_email_monitoring_snapshot_artifact` writes redacted watch, readiness, or traceability receipts to a configured private root and returns filename, bytes, SHA-256, and root hash without exposing the private path. | implemented with fixture tests; pending live configured snapshot root and hosted artifact install |
| GitHub Actions run | Hosted validation on the exact current PR-head candidate, including Rust baseline, CodeQL, custom query tests, mandatory Cobertura generation/artifact retention, optional capability-gated GitHub Code Quality reporting, DevSkim, OSV, and release-artifact where applicable. | this v2 candidate has no hosted validation or release-artifact proof recorded in this document; inspect the PR's exact head SHA and current hosted receipts |
| Reviewer signoff | Independent review for architecture/contract, safety/redaction, release readiness, and monitoring runbook coverage. | candidate-specific review evidence must name the exact PR head; no merge, release, install, or live proof is implied here |
| Promotion source | Hosted artifact or tagged commit only; no local binary promotion. | release-artifact workflow present; pending hosted run and checksum install |
| Rollback | Remove MCP alias or restore previous hosted artifact. | deferred until install |

Operational posture: no-send-only and not production-ready until hosted
validation, reviewer findings, the hard-bounce blocker, degraded live log
evidence gaps, and private ledger configuration are resolved. Optional GitHub
Code Quality reporting is not provider or send readiness. Accepting the
operational gaps can only mean remaining paused or seed-only; it is not
production monitoring readiness.
